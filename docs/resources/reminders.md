# Reminders (Mahnungen)

API wrapper for payment reminders under `/reminders` and their two sub-resources (`/reminder-items`, `/reminder-tags`).

## Access

```php
$billomat->reminders         // reminders
$billomat->reminders->items  // line items of a reminder (read-only)
$billomat->reminders->tags   // tags
```

The configurable reminder text blocks live in a separate resource: `$billomat->reminderTexts` (see `ReminderTextsApi`).

## Model

A reminder **always** references an underlying invoice via `invoiceId` (required on `create`). Content and line items are generated by Billomat from the original invoice plus the selected reminder text block (`reminderTextId`), so the `reminder-items` are read-only.

The lifecycle is status-driven:

```
DRAFT  ── complete() ──▶  OPEN  ── invoice is paid ──▶  PAID
  │                        │
  │                        ├── due date passed ──▶  OVERDUE
  │                        │
  │                        └── cancel() ──▶  CANCELED  ── uncancel() ──▶  OPEN
  └── delete() (any status; prefer cancel() once completed)
```

An open reminder can be followed by further dunning levels: Billomat increments the level internally and uses the templates stored as dunning levels in `reminderTexts` (see [Reminder levels](settings-reminder-levels.md)).

## Methods

### Reminders

#### `list(ReminderFilter|array $filters = []): list<Reminder>`

Billomat filters by `client_id`, `contact_id`, `invoice_id`, `invoice_number`, `status`, `from`, `to`, `tags` and more.

The typed filter `ReminderFilter` is recommended. Its camelCase fields are `clientId`, `contactId`, `invoiceNumber`, `status` (`list<ReminderStatus>`), `from`/`to` (`DateTimeImmutable`), `label`, `subject`, `intro`, `note`, `tags` and `articleId`. Multi-value fields are lists and are sent comma-separated. On top of that there are `orderBy`, `page`, `perPage` and `extra` for further query parameters (e.g. `invoice_id`). A plain array still works: it is passed through to the query string as is, and array values are sent as `key[]=…`.

```php
use Justpilot\Billomat\Api\OrderBy;
use Justpilot\Billomat\Api\ReminderFilter;
use Justpilot\Billomat\Model\Enum\ReminderStatus;

$overdue = $billomat->reminders->list(new ReminderFilter(
    status: [ReminderStatus::OVERDUE],
    orderBy: OrderBy::asc('due_date'),
));
```

`listPage()` takes the same filters and returns a `Page` with pagination metadata; `iterateAll()` walks through all pages lazily. See [Pagination and filtering](../concepts/pagination-and-filtering.md).

#### `get(int $id): ?Reminder`

Returns `null` on 404. Embedded `reminder-items` are hydrated automatically. `getOrFail()` throws a `NotFoundException` instead of returning `null`.

#### `create(ReminderCreateOptions $options): Reminder`

Only `invoiceId` is required. Billomat takes the address, reminder text, due date etc. from the invoice or the client configuration unless you override them.

```php
use Justpilot\Billomat\Api\ReminderCreateOptions;

$opts = new ReminderCreateOptions(
    invoiceId: 9876,
    reminderTextId: 42,
    dueDays: 7,
    subject: 'Payment reminder for invoice 2026-0042',
);

$reminder = $billomat->reminders->create($opts);
```

#### `update(int $id, ReminderUpdateOptions $options): Reminder`

Only advisable in status `DRAFT`. `invoiceId` can no longer be changed here; the link to the invoice is fixed.

#### `complete(int $id, ?int $templateId = null): void`

Status `DRAFT → OPEN`. An optional `templateId` forces a specific layout template.

#### `cancel(int $id): void` / `uncancel(int $id): void`

`cancel()` sets the status to `CANCELED`, `uncancel()` reactivates a canceled reminder (`CANCELED → OPEN`). Reminders have no `clear()`/`unclear()` (Billomat answers 404).

#### `email(int $id, ?EmailOptions $options = null): void`

Without options, Billomat uses all defaults from the configured email template.

```php
use Justpilot\Billomat\Api\EmailOptions;

$mail = new EmailOptions(to: ['client@example.com'], subject: 'Reminder: open invoice 2026-0042');

$billomat->reminders->email($reminder->id, $mail);
```


#### `mail(int $id, ?MailOptions $options = null): void`

Sends the reminder by post via the Pixelletter service. **This costs money.** `MailOptions` (colour, duplex, paper weight, extra attachments) is described on the [invoices page](invoices.md#write-model-mailoptions); without options Billomat uses the account defaults.

```php
use Justpilot\Billomat\Api\MailOptions;

$billomat->reminders->mail($id, new MailOptions(duplex: true));
```

#### `pdf(int $id, ?PdfType $type = null): ReminderPdf` / `pdfContent(int $id, ?PdfType $type = null): string`

`pdf()` returns a `ReminderPdf` model (metadata plus base64 body). `pdfContent()` appends `?format=pdf` and returns the binary PDF content directly; it throws an `UnexpectedResponseException` if the body is empty or doesn't start with `%PDF-`.

```php
$pdf = $billomat->reminders->pdf($reminder->id);                 // model
$raw = $billomat->reminders->pdfContent($reminder->id);        // string (PDF binary)
```

#### `uploadSignature(int $id, string $base64Pdf): void`

Attaches a PDF signed by the client to the reminder.

#### `delete(int $id): void`

Only works on reminders in status `DRAFT`.

### Reminder items (read-only)

```php
$items = $billomat->reminders->items->list($reminder->id);
$item = $billomat->reminders->items->get($itemId);
```

There is **no** `ReminderItemCreateOptions` and no write endpoint. Items show the original invoice amount and late fees, generated from the configured reminder text block.

### Reminder tags

```php
use Justpilot\Billomat\Api\ReminderTagCreateOptions;

$billomat->reminders->tags->create(
    $reminder->id,
    new ReminderTagCreateOptions(name: 'dunning-level-2'),
);

$tags = $billomat->reminders->tags->list($reminder->id);
$cloud = $billomat->reminders->tags->cloud(); // aggregated, with count
```

There is no update. To rename a tag, delete it and create it again.

## Write model: `ReminderUpdateOptions`

Mirrors `ReminderCreateOptions` **without** `invoiceId`; the link to the invoice is fixed. Fields left at `null` are stripped from the payload. `Clear::Field` instead sends the field as JSON `null`, and Billomat empties it, e.g. `new ReminderUpdateOptions(note: Clear::Field)`.

The reminder ID isn't part of the options: pass it as the first argument of `create()`, which adds `reminder_id` to the payload.

### Note on reminder items

There is **no** `ReminderItemCreateOptions` and no `ReminderItemUpdateOptions`. Reminder items are generated on the server from the original invoice and the reminder text block; they are read-only.

## Enums used

- [`ReminderStatus`](../../src/Model/Enum/ReminderStatus.php): `DRAFT`, `OPEN`, `OVERDUE`, `PAID`, `CANCELED`. Note: Billomat sets `OVERDUE` automatically once `dueDate` has passed; never send it yourself.
- [`PdfType`](../../src/Model/Enum/PdfType.php): shared PDF variants for `pdf()`.

There is **no** comment action key enum for reminders: reminders simply have no `/reminder-comments` resource. Activity is tracked in the comments of the underlying invoice.

## Pitfalls

- **`delete()` isn't limited to `DRAFT`.** Billomat's API deletes reminders in any status. Once completed, prefer `cancel()`: the document is numbered, and deleting it leaves a gap in the number sequence (GoBD).
- **`invoiceId` is required and immutable.** A reminder without an invoice doesn't exist; after `create()` the link is fixed and not part of `ReminderUpdateOptions`.
- **Items are read-only.** To add line items, adjust the reminder text block (`/reminder-texts`) or set a different `reminderTextId` before calling `complete()`.
- **No `/reminder-comments` endpoint.** The activity log and free-form notes belong to the parent invoice workflow, not to the reminder itself.
- **`dueDate` beats `dueDays`.** If both are set, the absolute `due_date` wins. It is cleaner to maintain only one of the two fields.
- **A `reminderTextId` without a matching entry in `/reminder-texts` leads to 422.** Before `create()`, make sure the reminder text block exists (via `$billomat->reminderTexts->list()`).
- **Status `OVERDUE` is read-only.** It is set on the server; the write models have no `status` field at all.
- **Multiple dunning levels for the same invoice are possible.** A second reminder for the same invoice automatically gets the next dunning level according to the levels configured in `reminderTexts` (`ReminderTextsApi`).
- **Tag cloud and list share the same endpoint.** `GET /reminder-tags` without `reminder_id` returns the aggregated cloud (`tag` wrapper); with `reminder_id` it returns the actual tags (`reminder-tag` wrapper). The SDK splits this into `cloud()` and `list()`.

## End-to-end example

```php
<?php

declare(strict_types=1);

require __DIR__ . '/vendor/autoload.php';

use Justpilot\Billomat\Api\EmailOptions;
use Justpilot\Billomat\Api\InvoiceFilter;
use Justpilot\Billomat\Api\OrderBy;
use Justpilot\Billomat\Api\ReminderCreateOptions;
use Justpilot\Billomat\Api\ReminderTagCreateOptions;
use Justpilot\Billomat\BillomatClient;
use Justpilot\Billomat\Model\Enum\InvoiceStatus;

$billomat = BillomatClient::create(
    billomatId: 'mycompany',
    apiKey: getenv('BILLOMAT_API_KEY'),
);

// 1) Pick an open invoice
$openInvoices = $billomat->invoices->list(new InvoiceFilter(
    clientId: 12345,
    status: [InvoiceStatus::OPEN],
    orderBy: OrderBy::asc('due_date'),
));

if ([] === $openInvoices) {
    exit('No open invoice to remind.');
}

$invoice = $openInvoices[0];

// 2) Choose a reminder text block (e.g. the first level)
$reminderTexts = $billomat->reminderTexts->list();
$firstStage = $reminderTexts[0] ?? null;

// 3) Create the reminder as a draft
$opts = new ReminderCreateOptions(
    invoiceId: $invoice->id,
    reminderTextId: $firstStage?->id,
    dueDays: 7,
    subject: 'Payment reminder for invoice ' . ($invoice->invoiceNumber ?? ''),
);

$reminder = $billomat->reminders->create($opts);
printf("Reminder #%d created (status: %s)\n",
    $reminder->id,
    $reminder->status?->label() ?? 'unknown',
);

// 4) Add a tag (e.g. the dunning level) before completing
$billomat->reminders->tags->create(
    $reminder->id,
    new ReminderTagCreateOptions(name: 'dunning-level-1'),
);

// 5) Complete: DRAFT → OPEN
$billomat->reminders->complete($reminder->id);

// 6) Send by email
$mail = new EmailOptions(
    to: ['client@example.com'],
    subject: 'Reminder: invoice still open',
    body: "Hello,\n\nplease settle our open invoice.\n\nBest regards",
);
$billomat->reminders->email($reminder->id, $mail);

// 7) Save the PDF locally
$pdfBinary = $billomat->reminders->pdfContent($reminder->id);
file_put_contents("reminder-{$reminder->id}.pdf", $pdfBinary);

// 8) Inspect the generated reminder items (read-only)
foreach ($billomat->reminders->items->list($reminder->id) as $item) {
    printf("- %s: %s\n", $item->title ?? 'Item', $item->total?->format(2) ?? '-');
}
```
